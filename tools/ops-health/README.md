# أدوات اختبار مراقبة الصحة (PR-1)

اختبارات بدون أي تبعيات (Node.js 18 أو أحدث) لمساري `workflows/ops/health-monitor.json` و`workflows/ops/global-error-handler.json`.

## التشغيل
من جذر المستودع:
```
node --test tools/ops-health/*.test.mjs
```

## ما الذي يُختبر
| الاختبار | الهدف |
|---|---|
| `active: false` | المساران يصلان غير فعّالين عند الاستيراد |
| أنواع العقد المسموحة | لا توجد عقد خارج القائمة المعتمدة |
| T0 | لا عقدة نموذج لغوي ولا نقطة نهاية لنموذج في أي مكان |
| GET فقط | كل طلبات HTTP من نوع GET |
| اعتماد n8n API | طلبات `/api/v1` تستخدم الاعتماد ولا تضع مفتاحاً يدوياً |
| لا أسرار في الملفات | لا رموز أو مفاتيح محفوظة في ملفات JSON |
| الجدولة | كل 15 دقيقة + يومياً 08:00 بتوقيت `Asia/Riyadh` |
| حجب الأسرار | رسائل المعالج العام والمراقب لا تحتوي أي سر |
| حقول التنبيه | اسم المسار، معرّف التنفيذ، الخطأ، الوقت |
| التنبيه | النبضة المتأخرة، المسار غير المفعّل، الإخفاق غير المغطى، انقطاع API |
| كتم التكرار | لا تكرار خلال ساعتين، ثم تذكير |
| التعافي | رسالة "تعافى" مرة واحدة عند زوال المشكلة |
| لا تعافٍ زائف | انقطاع API لا يُعلن تعافي مشاكل لم تُفحص |
| الملخص اليومي | يُرسل دائماً ولا يغيّر حالة الكتم |
| النبضة معطّلة | `Config` المعتمد لا يحتوي مسار نبضة، ولا يصدر تنبيه نبضة، والملخص يذكر أنها معطّلة |

اختبارات منطق النبضة (التأخر، الكتم، التعافي) تعمل بإعداد اختباري يفعّل النبضة، حتى يبقى المنطق مضموناً عند إعادة تفعيلها.

الاختبارات السلوكية تشغّل كود عقد Code المصدَّر نفسه (`Evaluate Health` و`Format Error Alert`) داخل محاكاة لبيئة n8n، فلا تحتاج اتصالاً بـ n8n أو Telegram.
