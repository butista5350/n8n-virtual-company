# دليل التشغيل: مراقب الصحة والتنبيهات ومعالج الأخطاء العام

| البند | القيمة |
|---|---|
| المسارات | `Ops Health Monitor` (`workflows/ops/health-monitor.json`) و`Global Error Handler` (`workflows/ops/global-error-handler.json`)، ويعتمد المراقب على `Heartbeat Check` (`workflows/heartbeat-check.json`) |
| المقعد المسؤول | مهندس مسارات n8n ومراقب الصحة والتنبيهات |
| مستوى النموذج | T0 (بدون أي عقدة نموذج لغوي أو استدعاء لنقطة نهاية نموذج) |
| الكلفة | 0$ |
| قناة التنبيه | Telegram - المحادثة المحددة في `telegram_chat_id` (القيمة الحقيقية تُضبط داخل n8n فقط) |
| الحالة عند الاستيراد | غير فعّالين (`"active": false`) |
| الاختبارات | `node --test tools/ops-health/*.test.mjs` |

## 1. Ops Health Monitor

### المشغّلات
- **كل 15 دقيقة:** فحص وإرسال تنبيهات عند ظهور خلل أو زواله.
- **يومياً 08:00 بتوقيت الرياض:** ملخص يُرسل دائماً حتى لو كانت كل الفحوصات سليمة. توقيت المسار مضبوط على `Asia/Riyadh`.

### الفحوصات (قراءة فقط - GET)
| الفحص | الطلب | يُطلق التنبيه عند |
|---|---|---|
| سلامة n8n | `GET /healthz` | أي رد غير 2xx أو تعذّر الاتصال |
| سلامة n8n API | `GET /api/v1/workflows` و`GET /api/v1/executions` | أي رد غير 2xx أو تعذّر الاتصال |
| المسارات المتوقعة | `GET /api/v1/workflows?limit=250` | مسار متوقع غير موجود أو غير مفعّل |
| حداثة النبضة | `GET /api/v1/executions?status=success&limit=1&workflowId=<Heartbeat Check>` | آخر تنفيذ ناجح أقدم من الحد (افتراضياً 30 دقيقة) أو لا يوجد |
| الإخفاقات غير المغطاة | `GET /api/v1/executions?status=error&limit=100` | تنفيذ فاشل خلال آخر 15 دقيقة لمسار ليس له `errorWorkflow` |

> **فحص النبضة مفعّل:** مسار النبضة هو `Heartbeat Check` (`workflows/heartbeat-check.json`)، ينفّذ كل 15 دقيقة، والحد الأقصى لعمر آخر نبضة ناجحة 30 دقيقة. لتعطيل الفحص مؤقتاً اترك `heartbeat_workflow_name` فارغاً وأزل الاسم من `expected_workflows` (تعديل يحتاج موافقة).

الإخفاقات في المسارات المرتبطة بمعالج أخطاء لا تُكرَّر هنا، لأن `Global Error Handler` يبلّغ عنها فوراً.

### كتم التكرار والتعافي
- كل مشكلة لها مفتاح ثابت (مثل `hb:stale` أو `wf:inactive:<الاسم>`).
- **أول ظهور:** تنبيه فوري.
- **استمرارها:** لا تكرار لمدة ساعتين، ثم تذكير واحد كل ساعتين ما دامت قائمة.
- **زوالها:** رسالة "تعافى" واحدة تذكر المشكلة ومدة استمرارها.
- إذا تعذّر فحص فئة ما (مثلاً انقطاع API)، لا تُعلَن مشاكل تلك الفئة "متعافية" زوراً، بل تبقى في الحالة حتى يُعاد فحصها.
- الحالة محفوظة في Static Data للمسار، وهذه لا تُحفظ إلا في التشغيل الإنتاجي (المسار منشور). التشغيل اليدوي لا يغيّرها.
- الملخص اليومي لا يغيّر حالة الكتم.

### حجب الأسرار
تُحجب قبل الإرسال رموز Telegram وGitHub (`ghp_`, `github_pat_`) ومفاتيح `sk-` وJWT وقيم `Bearer/Basic` وقيم الحقول `api_key/token/secret/password/authorization` وكلمات المرور داخل الروابط. تُقصّ رسائل الأخطاء الطويلة، ويُهرَّب النص لصيغة HTML في Telegram.

### الإعدادات (عقدة `Config`)
| الحقل | الافتراضي | الوصف |
|---|---|---|
| `n8n_base_url` | `http://127.0.0.1:5680` | عنوان n8n المحلي لطلبات API؛ لا يُستخدم العنوان العام |
| `expected_workflows` | `["Heartbeat Check","GitHub AI Assistant","MCP server","Telegram Approval","Global Error Handler"]` | مسارات يجب أن تكون موجودة ومفعّلة |
| `heartbeat_workflow_name` | `Heartbeat Check` | مسار النبضة؛ القيمة الفارغة تعطّل فحص النبضة |
| `heartbeat_max_age_minutes` | `30` | أقصى عمر لآخر نبضة ناجحة |
| `failure_lookback_minutes` | `15` | نافذة البحث عن الإخفاقات |
| `suppress_hours` | `2` | مدة كتم التكرار |
| `telegram_chat_id` | `REPLACE_WITH_TELEGRAM_CHAT_ID` | محادثة التنبيهات؛ تُستبدل داخل n8n بالمعرّف الحقيقي ولا تُحفظ في المستودع |

## 2. Global Error Handler

### كتم التكرار وسقف التنبيهات
- **الخطأ نفسه:** معرّف المسار + اسم العقدة + نص الخطأ بعد حذف الأرقام والمعرّفات الطويلة (12 حرفاً فأكثر وفيها رقم).
- **الكتم:** لا يُعاد التنبيه للخطأ نفسه مدة ساعتين؛ وأول تنبيه بعدها يذكر «تكرر: N مرة خلال فترة الكتم السابقة».
- **السقف الاحتياطي:** 6 تنبيهات في الساعة كحد أقصى؛ ما زاد يُعدّ ولا يُرسل، ثم تُرسل رسالة «N تنبيهات إضافية مكتومة» مع أول تنبيه بعد توفر سعة.
- **الحالة:** تُحفظ في الذاكرة الثابتة للمسار، وتُحذف مدخلات الكتم بعد 24 ساعة. رسالة المكتومات تُرسل عند أول خطأ تالٍ، لا بجدول زمني.
- **المشغّل:** Error Trigger، يعمل عند فشل أي مسار يحدد هذا المسار في إعداد "Error Workflow".
- **التنبيه الفوري يتضمن:** اسم المسار ومعرّفه، ومعرّف التنفيذ (أو "غير متاح" إذا فشل المُشغِّل نفسه)، والعقدة الفاشلة، وملخص الخطأ بعد حجب الأسرار، والوقت بتوقيت الرياض، والوضع، ورابط التنفيذ.
- لا يحتاج هذا المسار إلى أن يكون منشوراً ليعمل كمعالج أخطاء.

## 3. الاعتمادات المطلوبة
| الاعتماد | النوع | الاستخدام |
|---|---|---|
| `n8n API (monitor)` | n8n API | طلبات GET إلى `/api/v1` فقط |
| `Telegram account` | Telegram API | إرسال التنبيهات |

لا تُحفظ أي أسرار في ملفات المستودع؛ الملفات تشير إلى الاعتمادات بالاسم فقط، ومعرّف اعتماد Telegram فيها `REPLACE_ME` ومعرّف المحادثة `REPLACE_WITH_TELEGRAM_CHAT_ID`. المستودع عام: لا تُضف إليه عناوين IP أو معرّفات محادثات حقيقية (يفشل الاختبار عند ظهورها).

كل مسار جديد يحمل ملاحظة `Tier` في وصفه، وأسماء النماذج (إن وُجدت مستقبلاً) تُوضع في `Config` فقط.

## 4. التفعيل (بعد دمج PR-1 وبموافقة تنفيذية)
1. استورد `workflows/heartbeat-check.json` والملفين في n8n؛ ستصل غير فعّالة.
2. اربط الاعتمادين أعلاه، واستبدل `REPLACE_WITH_TELEGRAM_CHAT_ID` و`n8n_base_url` بالقيم الحقيقية داخل n8n فقط، وراجع بقية قيم `Config`.
3. فعّل `Heartbeat Check` وانتظر نبضة ناجحة واحدة.
4. شغّل `Ops Health Monitor` يدوياً مرة وتأكد من وصول الرسالة.
5. انشر `Ops Health Monitor`.
6. لكل مسار قائم يُراد تغطيته: Settings ← Error Workflow ← `Global Error Handler`. (تعديل أي مسار قائم يحتاج موافقة مستقلة.)

## 5. الاستجابة للتنبيهات
| التنبيه | الإجراء |
|---|---|
| n8n لا يستجيب لـ `/healthz` | تحقق من الحاوية/الخادم وسجلات n8n، ثم أعد التشغيل عند الحاجة |
| تعذّرت قراءة n8n API | تحقق من صلاحية مفتاح `n8n API (monitor)` ومن تفعيل Public API |
| مسار متوقع غير موجود/غير مفعّل | تحقق من الأرشفة أو إلغاء النشر في سجل النشاط، وأعد النشر بموافقة |
| تأخرت النبضة (عند تفعيل الفحص) | افتح تنفيذات مسار النبضة المحدد في `heartbeat_workflow_name` وتحقق من المشغّل والأخطاء |
| إخفاقات غير مغطاة | افتح التنفيذ المذكور، ثم اربط المسار بـ `Global Error Handler` |
| فشل مسار (من المعالج العام) | افتح رابط التنفيذ وعالج سبب الخطأ |

## 6. اختبارات القبول
قواعد: كل مسار اختباري يُنشأ بموافقة ويُعطَّل ويُؤرشف فور الانتهاء. لا Webhook عام في أي اختبار (تُستخدم مشغّلات الجدولة). التنفيذ اليدوي لا يُطلق Error Workflow ولا يحفظ Static Data، فاختبارات الكتم والتعافي بالجدولة فقط. القيم الوهمية لا تُحفظ في المستودع. لا تُغيَّر الاعتمادات ولا مفتاح n8n API.

A1 تنبيه فوري عند فشل مسار مغطّى
- الخطوات: مسار مؤقت ZZ Test Failure: مشغّل جدولة كل 5 دقائق + عقدة Code ترمي throw new Error('acceptance test'). اضبط Error workflow على Global Error Handler وفعّله.
- المتوقع: خلال 5 دقائق رسالة فيها اسم المسار والعقدة والسبب ورابط التنفيذ.
- الدليل: نص الرسالة بعد حجب المعرّفات.

A2 كتم التكرار في المعالج
- الخطوات: اترك المسار المؤقت 15 دقيقة (3 فشلات) وعُدّ الرسائل.
- المتوقع: رسالة واحدة فقط، والتنبيه التالي بعد انتهاء الكتم يذكر «تكرر N مرة».
- الدليل: عدد الرسائل.

A3 حجب الأسرار
- الخطوات: اجعل رسالة الخطأ تتضمن نصوصاً وهمية تشبه المفاتيح (token= متبوعة بـ12 حرفاً، وسلسلة بصيغة توكن GitHub مولَّدة عشوائياً).
- المتوقع: تظهر كـ[REDACTED...] ولا تظهر القيم.
- الدليل: نص الرسالة.

A4 مسار متوقع معطّل
- الخطوات: عطّل Heartbeat Check (بموافقة).
- المتوقع: خلال دورة 15 دقيقة رسالة «المسار المتوقع غير مفعّل: Heartbeat Check».
- الدليل: نص الرسالة ووقتها.

A5 التعافي
- الخطوات: أعد تفعيل Heartbeat Check.
- المتوقع: رسالة «تعافى» واحدة ثم صمت.
- الدليل: نص الرسالة.

A6 الملخص اليومي
- الخطوات: نفّذ يدوياً من عقدة Daily 08:00 Summary، وانتظر ملخص 08:00 في اليوم التالي.
- المتوقع: رسالة ملخص في الحالتين بتوقيت الرياض، بلا تغيير في حالة الكتم.
- الدليل: نصا الرسالتين.

A7 انقطاع واجهة n8n API
- الخطوات: في مسودة المراقب غيّر n8n_base_url مؤقتاً إلى منفذ خاطئ على العنوان المحلي وشغّل يدوياً، ثم أعد القيمة.
- المتوقع: رسالة critical تذكر تعذّر الاتصال، ولا رسالة تعافٍ زائفة.
- الدليل: نص الرسالة وتأكيد استعادة القيمة.

A8 النبضة الحيّة
- الخطوات: بعد 30 دقيقة من تفعيل Heartbeat Check راقب المراقب.
- المتوقع: لا تنبيه «تأخرت النبضة» ولا «لا يوجد تنفيذ ناجح».
- الدليل: رقم آخر تنفيذ ناجح للنبضة ووقته.

A9 اختبارات المستودع
- الخطوات: node --test tools/ops-health/*.test.mjs
- المتوقع: كلها ناجحة.
- الدليل: مخرجات الأمر.

A10 النظافة والأمن
- الخطوات: اختبار نظافة المستودع، ومراجعة رسائل Telegram المستلمة، وفحص تصدير المسارات من n8n.
- المتوقع: لا عنوان IP ولا معرّف محادثة ولا مفاتيح في أي منها.
- الدليل: نتيجة الفحص.

A11 سلامة بوابة الموافقة بعد الربط
- الخطوات: بعد ربط المعالج بـTelegram Approval أرسل طلب موافقة تجريبياً (0$ بلا أثر).
- المتوقع: يصل الطلب ويُستجاب له والمسار يعمل.
- الدليل: نتيجة الطلب.

التنظيف: عطّل وأرشف ZZ Test Failure، وتأكد أن Config عاد لقيمه، وسجّل نتائج A1 إلى A11 في جدول داخل وصف الـPR.

## 8. الاختبارات
```
node --test tools/ops-health/*.test.mjs
```
تتحقق من: `"active": false`، وGET فقط، وخلوّ المسارات من أي عقدة أو نقطة نهاية لنموذج لغوي، وحجب الأسرار وعدم وجودها في الملفات، وكتم التكرار ساعتين ثم التذكير، وكتم أخطاء المعالج المتكررة ساعتين وسقف 6 تنبيهات في الساعة، وإشعار التعافي، وعدم إعلان تعافٍ زائف عند انقطاع API، والملخص اليومي، وأن الإعداد المعتمد يفعّل فحص النبضة ويضم المسارات الخمسة المتوقعة، وأن تعطيل النبضة بقيمة فارغة لا يُطلق تنبيهاً، ووجود ملاحظة `Tier: T0`، وخلوّ كل ملفات المستودع من عناوين IP أو معرّفات محادثات Telegram حقيقية. التفاصيل في `tools/ops-health/README.md`.
