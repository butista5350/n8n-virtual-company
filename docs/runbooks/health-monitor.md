## 1. Ops Health Monitor

### المشغّلات
- **كل 15 دقيقة:** فحص وإرسال تنبيهات عند ظهور خلل أو زواله.
- **يومياً 08:00 بتوقيت الرياض:** ملخص يُرسل دائماً حتى لو كانت كل الفحوصات سليمة. توقيت المسار مضبوط على `Asia/Riyadh`.

### الفحوصات (قراءة فقط - GET)
| الفحص | الطلب | يُطلق التنبيه عند |
|---|---|---|
| سلامة n8n | `GET /healthz` | أي رد غير 2xx أو تعذّر الاتصال |
| سلامة n8n API | `GET /api/v1/workflows` و`GET /api/v1/executions` | أي رد غير 2xx أو تعذّر الاتصال |
| المسارات المتوقعة | `GET /api/v1/workflows?limit=250` | مسار متوقع غير موجود أو غير مفعّل |
| حداثة النبضة (معطّل حالياً) | `GET /api/v1/executions?status=success&limit=1&workflowId=<Heartbeat>` | آخر تنفيذ ناجح أقدم من الحد (افتراضياً 30 دقيقة) أو لا يوجد |

> **فحص النبضة معطّل مؤقتاً:** لا يوجد مسار نبضة في هذا المشروع حالياً (الاختبار الحي لم يجد `Heartbeat Check`). لذلك `heartbeat_workflow_name` فارغ و`Heartbeat Check` غير مدرج في `expected_workflows`. لإعادة التفعيل بعد إنشاء/ربط مسار النبضة: ضع اسمه في `heartbeat_workflow_name` وأضفه إلى `expected_workflows` (تعديل يحتاج موافقة).
| الإخفاقات غير المغطاة | `GET /api/v1/executions?status=error&limit=100` | تنفيذ فاشل خلال آخر 15 دقيقة لمسار ليس له `errorWorkflow` |

الإخفاقات في المسارات المرتبطة بمعالج أخطاء لا تُكرَّر هنا، لأن `Global Error Handler` يبلّغ عنها فوراً.

### كتم التكرار والتعافي
- كل مشكلة لها مفتاح ثابت (مثل `hb:stale` أو `wf:inactive:<الاسم>`).
- **أول ظهور:** تنبيه فوري.
- **استمرارها:** لا تكرار لمدة ساعتين، ثم تذكير واحد كل ساعتين ما دامت قائمة.
- **زوالها:** رسالة "تعافى" واحدة تذكر المشكلة ومدة استمرارها.
- إذا تعذّر فحص فئة ما (مثلاً انقطاع API)، لا تُعلَن مشاكل تلك الفئة "متعافية" زوراً، بل تبقى في الحالة حتى يُعاد فحصها.
- الحالة محفوظة في Static Data للمسار، وهذه لا تُحفظ إلا في التشغيل الإنتاجي (المسار منشور). التشغيل اليدوي لا يغيّرها.
- الملخص اليومي لا يغيّر حالة الكتم.

### حجب الأسرار
تُحجب قبل الإرسال رموز Telegram وGitHub (`ghp_`, `github_pat_`) ومفاتيح `sk-` وJWT وقيم `Bearer/Basic` وقيم الحقول `api_key/token/secret/password/authorization` وكلمات المرور داخل الروابط. تُقصّ رسائل الأخطاء الطويلة، ويُهرَّب النص لصيغة HTML في Telegram.

### الإعدادات (عقدة `Config`)
| الحقل | الافتراضي | الوصف |
|---|---|---|
| `n8n_base_url` | `http://178.238.225.172:5680` | عنوان n8n لطلبات API |
| `expected_workflows` | `["Telegram Approval"]` | مسارات يجب أن تكون موجودة ومفعّلة |
| `heartbeat_workflow_name` | فارغ (الفحص معطّل) | مسار النبضة؛ القيمة الفارغة تعطّل فحص النبضة |
| `heartbeat_max_age_minutes` | `30` | أقصى عمر لآخر نبضة ناجحة |
| `failure_lookback_minutes` | `15` | نافذة البحث عن الإخفاقات |
| `suppress_hours` | `2` | مدة كتم التكرار |
| `telegram_chat_id` | `1208634276` | محادثة التنبيهات |

## 2. Global Error Handler
- **المشغّل:** Error Trigger، يعمل عند فشل أي مسار يحدد هذا المسار في إعداد "Error Workflow".
- **التنبيه الفوري يتضمن:** اسم المسار ومعرّفه، ومعرّف التنفيذ (أو "غير متاح" إذا فشل المُشغِّل نفسه)، والعقدة الفاشلة، وملخص الخطأ بعد حجب الأسرار، والوقت بتوقيت الرياض، والوضع، ورابط التنفيذ.
- لا يحتاج هذا المسار إلى أن يكون منشوراً ليعمل كمعالج أخطاء.

## 3. الاعتمادات المطلوبة
| الاعتماد | النوع | الاستخدام |
|---|---|---|
| `n8n API (monitor)` | n8n API | طلبات GET إلى `/api/v1` فقط |
| `Telegram account` | Telegram API | إرسال التنبيهات |

لا تُحفظ أي أسرار في ملفات المستودع؛ الملفات تشير إلى الاعتمادات بالاسم فقط.

## 4. التفعيل (بعد دمج PR-1 وبموافقة تنفيذية)
1. استورد الملفين في n8n؛ سيصلان غير فعّالين.
2. اربط الاعتمادين أعلاه، وراجع قيم `Config`.
3. شغّل `Ops Health Monitor` يدوياً مرة وتأكد من وصول الرسالة.
4. انشر `Ops Health Monitor`.
5. لكل مسار قائم يُراد تغطيته: Settings ← Error Workflow ← `Global Error Handler`. (تعديل أي مسار قائم يحتاج موافقة مستقلة.)

## 5. الاستجابة للتنبيهات
| التنبيه | الإجراء |
|---|---|
| n8n لا يستجيب لـ `/healthz` | تحقق من الحاوية/الخادم وسجلات n8n، ثم أعد التشغيل عند الحاجة |
| تعذّرت قراءة n8n API | تحقق من صلاحية مفتاح `n8n API (monitor)` ومن تفعيل Public API |
| مسار متوقع غير موجود/غير مفعّل | تحقق من الأرشفة أو إلغاء النشر في سجل النشاط، وأعد النشر بموافقة |
| تأخرت النبضة (عند تفعيل الفحص) | افتح تنفيذات مسار النبضة المحدد في `heartbeat_workflow_name` وتحقق من المشغّل والأخطاء |
| إخفاقات غير مغطاة | افتح التنفيذ المذكور، ثم اربط المسار بـ `Global Error Handler` |
| فشل مسار (من المعالج العام) | افتح رابط التنفيذ وعالج سبب الخطأ |

## 6. التراجع
1. ألغِ نشر `Ops Health Monitor`، وأزل `Global Error Handler` من إعداد Error Workflow في المسارات المرتبطة.
2. نفّذ `git revert` لـ commit حزمة PR-1 على `dev` (أو على `main` بعد الدمج).
